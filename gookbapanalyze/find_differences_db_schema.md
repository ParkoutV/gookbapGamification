# 다른그림찾기 이미지 데이터베이스 추상화 구조

요청하신 조건에 맞추어 기본 사진과 파츠를 분리하고, 무작위 조립(랜덤 갈아끼우기)이 가능하도록 테이블을 정규화한 구조를 제안합니다. MySQL과 같은 관계형 데이터베이스 환경에서 데이터의 중복을 막고 확장을 쉽게 만들기 위해, 사진 내에 파츠가 배치될 '슬롯(위치 좌표)'과 해당 슬롯에 들어갈 수 있는 '파츠 그룹(카테고리)'을 매핑하는 것이 핵심입니다.

## 1. 테이블 관계도 (ERD 요약)
- **base_images**: 배경이 되는 원본 사진을 저장합니다.
- **part_categories**: 파츠의 종류(예: 국밥류, 반찬류, 간판류 등)를 분류하여 무작위 교체의 기준을 만듭니다.
- **parts**: 실제 덧씌워질 개별 투명화 이미지(예: 맑은국밥, 마라국밥)를 저장합니다.
- **image_slots**: 특정 배경 사진에서 파츠가 위치할 X, Y 좌표와 적용될 파츠 카테고리를 연결합니다.

## 2. 상세 테이블 명세서

### 2.1. 기본 사진 테이블 (base_images)
여러 장의 기본 배경 이미지를 저장하는 테이블입니다.

| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
|---|---|---|---|
| id | INT | PK, Auto Increment | 기본 사진 고유 ID |
| title | VARCHAR(100) | NOT NULL | 사진 제목 (예: 국밥집 밥상 풍경) |
| image_url | VARCHAR(255) | NOT NULL | 기본 사진 파일 경로 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 등록일자 |

### 2.2. 파츠 카테고리 테이블 (part_categories)
비슷한 성격의 파츠들을 묶어 무작위 추출의 풀(Pool)을 형성하기 위한 테이블입니다. 정규화를 위해 파츠 테이블과 슬롯 테이블 사이의 연결 고리 역할을 합니다.

| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
|---|---|---|---|
| id | INT | PK, Auto Increment | 카테고리 고유 ID |
| name | VARCHAR(50) | NOT NULL | 카테고리명 (예: 메인_국밥그릇) |

### 2.3. 개별 파츠 테이블 (parts)
덧씌우기할 개별 파츠 이미지(맑은국밥, 흰색국밥 등)를 저장하며, 각 파츠는 특정 카테고리에 속하게 됩니다.

| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
|---|---|---|---|
| id | INT | PK, Auto Increment | 파츠 고유 ID |
| category_id | INT | FK | 속한 카테고리 ID (part_categories.id) |
| name | VARCHAR(50) | NOT NULL | 파츠명 (예: 마라국밥) |
| image_url | VARCHAR(255) | NOT NULL | 파츠 이미지 파일 경로 (배경 투명화) |

### 2.4. 슬롯(위치) 배치 테이블 (image_slots)
특정 사진의 어느 위치에 어떤 카테고리의 파츠가 들어갈 수 있는지 지정하는 테이블입니다. 이를 통해 하나의 사진에 여러 개의 '다른 그림 포인트'를 독립적으로 생성할 수 있습니다.

| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
|---|---|---|---|
| id | INT | PK, Auto Increment | 슬롯 고유 ID |
| base_image_id | INT | FK | 기준이 되는 사진 ID (base_images.id) |
| category_id | INT | FK | 해당 위치에 허용되는 파츠 카테고리 ID |
| x_coordinate | INT | NOT NULL | 파츠가 렌더링될 X 좌표 |
| y_coordinate | INT | NOT NULL | 파츠가 렌더링될 Y 좌표 |
| z_index | INT | DEFAULT 1 | 겹칠 경우의 Z축 렌더링 우선순위 |

## 3. 데이터 흐름 및 랜덤 생성 로직 구현 방식
위와 같이 정규화된 데이터베이스를 바탕으로 게임 로직을 구성하는 흐름은 다음과 같습니다.

1. **배경 및 문제 구성**: 웹 서버에서 base_images 중 무작위로 하나의 사진(예: id=1)을 불러옵니다.
2. **배치 영역(슬롯) 탐색**: image_slots 테이블에서 base_image_id=1에 속하는 레코드들을 모두 조회하여, 원본 사진의 어느 좌표(x, y)에 파츠를 올려야 하는지 파악합니다.
3. **무작위 파츠 맵핑**:
    - 조회된 각 슬롯에 지정된 category_id(예: 메인_국밥그릇)를 확인합니다.
    - parts 테이블에서 해당 category_id를 가진 파츠들(맑은국밥, 흰색국밥, 마라국밥 등)을 대상으로 무작위(Random) 조회를 실행하여 파츠를 하나씩 선택합니다.
    - 원본과 정답 비교를 위해, 이 과정을 두 번 거치면 왼쪽 화면(원본 느낌)과 오른쪽 화면(갈아끼워진 다른 그림) 세트를 만들 수 있습니다.
4. **클라이언트 화면 렌더링**: 추출된 사진과 파츠 데이터(이미지 경로, X/Y 좌표)를 프론트엔드로 전달합니다. HTML의 absolute 포지셔닝이나 `<canvas>` 객체 등을 활용해 원본 사진 위에 무작위로 선택된 파츠들을 덧씌워 최종 화면을 출력합니다.

이러한 구조로 설계하시면 원본 사진 테이블과 파츠 테이블이 완벽히 분리되며, 향후 새로운 메뉴(파츠)나 배경 사진을 추가하더라도 데이터베이스 구조 변경 없이 행(Row) 데이터만 추가하여 유연하게 확장할 수 있습니다.
