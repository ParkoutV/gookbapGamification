# 클라이언트 작업 로드맵 (2026-08-05 회의 기준)

출처: `docs/client/20260805.md`의 할 일 9개를 성격별로 묶은 것.
**세션이 바뀌어도 이 문서를 먼저 읽고 이어서 진행할 것.** 항목을 끝내면 체크박스를 채우고,
중간에 알게 된 제약이나 결정은 해당 단계의 "메모"에 남긴다.

## 진행 순서와 그 이유

`C1 → A → B → C2`

- **C1(첫 진입 시퀀스)을 맨 앞에 두는 이유**: 로딩·튜토리얼·TERM은 전부 첫 진입 흐름에
  끼어드는 화면이라 따로 만들면 서로 충돌한다. 또 A에서 톤을 바꾼 뒤에 새 화면 3개를
  만들면 톤을 두 번 맞춰야 한다.
- **A(톤)가 B(연출)보다 먼저인 이유**: 파티클 색·모션·룰렛 그래픽이 확정된 톤을 따라간다.
- **C2(랭킹)를 뒤로 뺀 이유**: 나머지와 독립적이고, 서버(`gookbapanalyze`) API 확인이
  선행되어야 해서 대기가 생길 수 있다.

**구현 완료, 브라우저 검증 대기** (브랜치 `feat/first-run-sequence`, 2026-08-06).
설계는 `docs/superpowers/specs/2026-08-06-first-run-sequence-design.md`,

병합 전 남은 일 2가지:
1. **TERM 본문 확정** — 현재 문구는 실제 수집 항목(익명 쿠키·게임 점수·설문 응답·쿠폰
   이력)을 근거로 쓴 초안이다. 구자건과 확정한 뒤 `app/lib/i18n/locales/{ko,en,ja}.ts`의
   `term.*` 문자열만 교체하면 된다(코드 변경 없음).
2. **브라우저 수동 확인** — 계획서 Task 5의 Step 5·6. 자동 테스트로 덮이지 않는 부분이
   있어서(이 저장소에는 React 훅/컴포넌트 테스트 인프라가 없다) 반드시 한 번은 눈으로
   봐야 한다. 특히 "1판 완주 → 뽑기 → 처음으로 → 2판"에서 스테이지가 갱신되는지.

메모:
- **TERM 노출 상태는 쿠키로만 관리한다(2026-08-06 결정, 이란토).** TERM은 동의를
  받아 보관해야 하는 계약이 아니라 **의무 고지**에 가깝다. 보통의 게임들처럼 "첫
  실행에만 띄운다"는 성격이므로, 봤는지 여부는 브라우저 로컬 상태로 충분하고
  서버 통신·DB 기록이 필요 없다. 서버에 동의 이력을 남기는 설계로 확장하지 말 것.
- 기존 `gookbapgame_token`(httpOnly, 참여자 식별용)과는 **별개의 쿠키**를 쓴다.
  이건 서버가 읽을 필요가 없으므로 httpOnly가 아니어도 되고, 만료는 토큰과 맞춰
  길게 잡는 게 자연스럽다(토큰이 2년).
- 쿠키가 지워지면 다시 뜨는데, 고지 성격상 그게 오히려 맞는 동작이다.

  화면 톤에서 튀는 문제였는데, 처음엔 "컬러 이모지 웹폰트는 10MB라 못 싣는다"고
  판단했다가 **흑백 Noto Emoji는 별개 폰트**라는 것을 확인했다. 원본 1.98MB를
  wght=400으로 고정하고 63자만 남겨 21KB다(`public/fonts/NotoEmoji-subset.woff2`).
  화면과 저장 이미지 모두 같은 폰트를 쓰므로 기기 상관없이 모양이 같다.
  자세한 제약은 `AGENTS.md`의 카드 항목 참고.
- 그래도 이모지를 그림 아이콘으로 바꾸고 싶다면 교체 지점은 `app/lib/couponEmoji.ts`의
  매핑 표 하나이고, 화면(`GatchaCard`)과 저장 이미지(`cardImage.ts`) 양쪽이 그 값을
  쓰므로 **둘 다 고쳐야 한다**. 다만 지금은 톤 문제가 해소돼서 급하지 않다.

## B. 연출 (사운드 + 애니메이션)

- [x] 사운드 이펙트 구현 (재생 훅 `app/lib/sfx.ts`, 음소거 토글 포함)
- [x] 랜덤뽑기 그래픽 요소 구현 — **룰렛이 아니라 카드 뒤집기로 확정**
- [x] 만점자 이펙트 (파티클 애니메이션) — **사운드는 넣지 않기로 했다**

메모:
- **연출 형태가 룰렛 → 카드 뒤집기로 바뀌었다(2026-08-07, 이란토).** 연출은
  `useCouponFlow`의 `wheel` 단계에 붙는다(단계 이름만 `wheel`로 남았다).
  뒷면 애셋 `public/icons/card-back.webp`, 앞면 `card-front.webp`(둘 다 1000x1371
  픽셀 아트). 탭하면 뒤집히고 앞면에 이모지·상품명·QR·만료일이 나온다(`GatchaCard.tsx`).
  앞면은 트럼프 카드 구조 — 안쪽 테두리의 좌상/우하를 정사각으로 파고 그 자리에
  상품 이모지를 대각선 대칭으로 놓는다.
  - draw는 여전히 마운트 시 1회다. 탭은 이미 받아둔 결과를 보여줄 뿐 API를 부르지 않는다.
  - 카드를 쓰는 결과는 `won`/`miss` 둘뿐이다. `wonButHidden`은 앞면에 올릴 payload가
    아예 없고(couponType·couponId 모두 없음), `rejected`/`error`는 뽑기가 소진되지
    않은 상태라 카드를 뒤집으면 소비한 것처럼 보인다 — 이 셋은 기존 텍스트 분기를 쓴다.
  - i18n 키 이름은 `wheel.*` 그대로 두고 값만 카드 표현으로 바꿨다(en/ja는 초안, 검토 필요).
- **효과음(2026-08-07).** 음원은 이란토가 만든 것으로 기획 폴더에 opus 원본이 있고,
  리포에는 m4a 변환본만 둔다(iOS Safari가 .ogg를 못 읽는다 — `docs/build-sfx.sh`).
  붙인 자리: 정답(`pencil_success`), 오답(`pencil_failed`), 카드 뒤집기·시작 버튼(`touch`),
  당첨(`coupon`), 꽝(`coupon_lose`), 게임 종료 후 결과표(`coindrop`).
  결과표 소리는 만점자 전용이 아니라 점수와 무관하게 항상 난다(2026-08-07, 이란토).
  좌상단에 음소거 토글을 뒀다 — 매장·공공장소에서 소리를 못 켜는 상황이 흔하다.
  제약은 `AGENTS.md`의 효과음 항목 참고(제스처 잠금 해제가 핵심).
- **만점자 이펙트(2026-08-07).** 1953점(= `1953 Master` 등급)일 때 결과표에 폭죽
  파티클이 5초간 흩날린다(`app/components/Confetti.tsx`, canvas).
  - **사운드는 넣지 않는다(이란토).** 결과표의 `coindrop`이 이미 울리고, 만점자에게만
    소리를 하나 더 얹을 이유가 없다는 판단.
  - **색은 무지개 파스텔로, 이곳만 테마 색을 따르지 않는 예외다(이란토).** 축하 연출이라
    화면에서 튀는 것이 목적이다. 톤 통일한다고 우드톤으로 되돌리지 말 것.
  - `prefers-reduced-motion`이면 아무것도 그리지 않는다.
- **이미지 저장(공유) 추가.** 로드맵에 없던 항목인데 작업 중 이란토가 요청했다.
  당첨 카드에만 붙는다(꽝은 남길 것이 없다). 모바일은 공유 시트로 "앨범에 저장"까지
  이어지고, 지원하지 않는 브라우저는 파일 다운로드로 떨어진다. 구현 제약은
  `AGENTS.md`의 카드 항목 참고(프리렌더 필수, 화면/캔버스 좌표 이중 관리).
- **등급(레어 등) 표시는 넣지 않기로 했다(2026-08-07, 이란토).** 애초에 등급이라는
  개념이 시스템에 없다 — `coupon_effects`에 등급 컬럼이 없고, 확률은
  `probability: {case_id: 0.05}`처럼 **점수 구간별**로 흩어져 있어서 "레어"는 상품
  속성이 아니라 뽑힌 구간에서의 그 상품 확률이 낮았다는 뜻이 될 뿐이다. 없는 개념을
  클라이언트에서 지어내지 않는다. 나중에 정말 필요해지면 상품별 등급을 DB에 두는 것이
  먼저지, 확률로 역산할 일이 아니다.
