**세션이 바뀌어도 이 문서를 먼저 읽고 이어서 진행할 것.** 항목을 끝내면 체크박스를 채우고,
중간에 알게 된 제약이나 결정은 해당 단계의 "메모"에 남긴다.

## 진행 순서와 그 이유

`C1 → A → B → C2`

- **C1(첫 진입 시퀀스)을 맨 앞에 두는 이유**: 로딩·튜토리얼·TERM은 전부 첫 진입 흐름에
  끼어드는 화면이라 따로 만들면 서로 충돌한다. 또 A에서 톤을 바꾼 뒤에 새 화면 3개를
  만들면 톤을 두 번 맞춰야 한다.
- **A(톤)가 B(연출)보다 먼저인 이유**: 파티클 색·모션·룰렛 그래픽이 확정된 톤을 따라간다.
- **C2(랭킹)를 뒤로 뺀 이유**: 나머지와 독립적이고, 서버(`gookbapanalyze`) API 확인이
  선행되어야 해서 대기가 생길 수 있다.

## C1. 첫 진입 시퀀스 (한 덩어리로 작업)

목표 흐름: `TERM 동의 → 로딩 → 튜토리얼 → 게임`

- [ ] 개인정보처리방침(TERM) 안내 페이지 — 최초 접속 시 노출
- [ ] 로딩 화면
- [ ] 튜토리얼 구성

메모:
- **TERM 노출 상태는 쿠키로만 관리한다(2026-08-06 결정, 이란토).** TERM은 동의를
  받아 보관해야 하는 계약이 아니라 **의무 고지**에 가깝다. 보통의 게임들처럼 "첫
  실행에만 띄운다"는 성격이므로, 봤는지 여부는 브라우저 로컬 상태로 충분하고
  서버 통신·DB 기록이 필요 없다. 서버에 동의 이력을 남기는 설계로 확장하지 말 것.
- 기존 `gookbapgame_token`(httpOnly, 참여자 식별용)과는 **별개의 쿠키**를 쓴다.
  이건 서버가 읽을 필요가 없으므로 httpOnly가 아니어도 되고, 만료는 토큰과 맞춰
  길게 잡는 게 자연스럽다(토큰이 2년).
- 쿠키가 지워지면 다시 뜨는데, 고지 성격상 그게 오히려 맞는 동작이다.
