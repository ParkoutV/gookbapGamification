# 법률 문서 3종을 대시보드에서 관리하기 — `gookbapanalyze` 인수인계

수신: `gookbapanalyze` 담당(구자건 팀장 / 그쪽 AGENTS)
발신: `gookbapgame`(클라이언트, 함이로)
작성: 2026-08-20

이용약관 · 개인정보처리방침 · 쿠폰 이용안내 3종의 대시보드 이관 건.

**갱신(2026-08-20 오후): 저쪽 `agreements` 테이블과 편집 페이지가 이미 올라왔고
(`740eec5`), 클라이언트도 그것을 읽도록 붙였다.** 2절의 요청 사항은 대부분 충족됐으므로
기록으로 남기고, **지금 남은 일은 5절**이다.

## 1. 현황 — 지금 어디에 어떤 모양으로 있나

| 항목 | 값 |
|---|---|
| 파일 | `gookbapgame/app/lib/legalDocs.ts` (415행) — **이관 후에는 폴백 역할** |
| 문서 | `terms`(이용약관) · `privacy`(개인정보처리방침) · `coupon`(쿠폰 이용안내) |

| 읽는 곳 | `LegalNotice.tsx`(약관·개인정보처리방침 탭 창), `CouponGuideNotice.tsx`(쿠폰 안내 팝업) |

원문 출처는 기획자가 확정해 전달한 `docs/client/20260813_약관.zip`이고, 연락처·시행일은
2026-08-19에 이란토가 채웠다(본사 개인정보처리방침 9·10조 기준, 시행일 2026-08-21).
**전사본이라 원문에 손대지 않는 것이 원칙이다.**

### 화면에서 열리는 경로

- 약관 · 개인정보처리방침: **최초 실행 고지**(닫기 없음, '확인'만) + **시작 화면 푸터**의
  재열람 링크. 후자가 개인정보처리방침을 다시 볼 수 있는 **유일한 통로**다.
- 쿠폰 이용안내: 뽑기 화면과 '내 쿠폰' 보관함에서 각자 팝업으로. **약관 창의 탭이 아니다** —
  쿠폰을 받는 자리에서 조건을 읽을 수 있어야 한다는 이유로 일부러 갈라놨다(2026-08-14).

## 2. 저쪽에 필요한 것 (요청 사항)

> **확정된 실물 계약(2026-08-20).** 아래 요청과 대체로 일치하며, 갈린 곳은 `locale`이
> 컬럼이 아니라 `body` 안의 키라는 점 하나다. 클라이언트는 이 형태에 맞춰 붙였다.
>
> ```
> agreements
>   doc_id      varchar  PK   -- 'terms' | 'privacy' | 'coupon'
>   body        jsonb         -- {"ko": "...", "en": "..."} 다국어 맵
>   updated_at  timestamptz
> RLS: Everyone SELECT (anon 직접 조회, RPC 불필요)
> ```
>
> 로케일 칸은 `supported_languages`의 `is_active` 목록을 따라 열린다.

### 2.1 테이블

문서를 담을 테이블 하나면 된다. 컬럼 이름은 그쪽 관례를 따라도 되지만 **무엇이 필요한지**는
아래와 같다.

```
legal_documents
  doc_id      text     -- 'terms' | 'privacy' | 'coupon' (클라이언트가 이 값으로 찾는다)
  locale      text     -- 'ko' | 'en'
  body        text     -- 평문 본문 (아래 3절의 서식 규칙을 지킬 것)
  updated_at  timestamptz
  PRIMARY KEY (doc_id, locale)
```

- **`body`를 jsonb 다국어 맵으로 만들지 말 것을 권한다.** `coupon_effects.coupon_type`이
  `text`에 JSON 문자열로 들어 있어 클라이언트가 `JSON.parse`로 펴고 있는데, 그 경계에서
  실제 사고가 났었다. 문서는 로케일당 한 행이 단순하고 대시보드 편집기와도 잘 맞는다.
- **HTML/마크다운을 넣지 말 것.** 클라이언트는 `whitespace-pre-line`으로 평문을 그대로
  그린다. 태그가 오면 그대로 글자로 보인다. 서식이 필요하면 먼저 상의할 것.

### 2.2 읽기 권한

- anon이 **직접 SELECT**할 수 있게 `Everyone: SELECT` RLS면 충분하다
  (`coupon_effects` · `web_coupon_settings` · `tracks`와 같은 성격). 별도 RPC는 필요 없다.
- RPC로 감쌀 거라면 **함수 이름과 반환 컬럼을 확정해서 알려줄 것.** 이 저장소에서
  가장 여러 번 난 사고가 "저쪽 문서에 적힌 반환 컬럼이 실물과 다름"이다
  (`ranking_view`의 `nickname_number` 누락으로 랭킹 네 탭이 전부 죽었던 건, `valid_from`이
  실제로는 오는데 문서에 없던 건). **문서가 아니라 실물 기준으로 알려줄 것.**

### 2.3 대시보드 편집 화면에서 막아줘야 하는 것

법률 문서라 조용히 틀리면 그대로 법적 리스크가 된다. 편집 UI에서 아래를 막아주면 좋겠다.

1. **빈 본문 저장 금지.** 지금 클라이언트 테스트가 "각 문서가 200자 이상"을 검사한다.
   빈 값이 오면 화면에 빈 창이 뜬다.
2. **`[YYYY년 MM월 DD일]` 같은 대괄호 자리표시자 저장 금지.** 실제로 자리표시자가 남은 채
   배포될 뻔해서 클라이언트에 검사를 박아뒀다.
3. **`ko`와 `en`을 짝으로 관리.** 한쪽만 갱신되면 언어에 따라 다른 내용을 보게 된다.
   ja/zh 사용자는 en 본문을 보므로(아래 3.2) en이 비면 그들에게 본문이 사라진다.
4. **시행일·연락처 줄이 사라지지 않게.** 2026-08-14에 전사 중 문서 끝이 잘려 개인정보
   처리방침 11항과 연락처·시행일이 통째로 빠진 채 커밋된 적이 있다. 앞부분이 멀쩡해서
   **눈으로는 드러나지 않는 종류의 사고**다.

## 3. 옮길 때 깨뜨리면 안 되는 것 (클라이언트 쪽 제약)

### 3.1 서식은 평문 규칙을 그대로 지킨다

- 문단 구분은 빈 줄, 글머리 기호는 **가운뎃점 + 공백(`· `)**. 원본 docx의 표 2개
  (위탁 / 국외이전)는 `라벨: 값` 줄로 폈다 — 표를 그대로 덤프하면 값이 라벨 없이 이어져
  읽을 수 없다.
- 곡선 따옴표(`“회사”`)까지 원문을 따른다. 정규화하지 말 것.

### 3.2 로케일은 ko/en 2종이다 — 4종으로 늘리지 말 것

UI 문구는 ko/en/ja/zh 4종이지만 법률 본문은 2종이다(2026-08-14, 이란토 결정).
한국 이벤트를 규율하는 한국 법률 문서이고, 개인정보보호법 제28조의8 인용처럼 **오역이 곧
법적 리스크**인 문장이 들어 있다. ja/zh 사용자는 UI 폴백 체인과 무관하게 **en을 본다**
(`pickLegalLocale`).

대시보드에서 ja/zh 칸을 열어 두면 언젠가 기계번역이 채워진다. **열지 말 것을 권한다.**
넣게 된다면 원어민 감수를 전제로 별도 합의가 필요하다.

### 3.3 조회 실패가 곧 "고지 없음"이 되면 안 된다

개인정보처리방침은 **최초 실행 고지의 대상**이고, 푸터 링크가 재열람의 유일한 통로다.
네트워크가 불안정한 매장에서 조회가 실패했다고 빈 창이 뜨면 고지 의무를 못 지킨 것이 된다.

→ **번들에 기존 본문을 폴백으로 남기기로 했다**(2026-08-20 확정). 조회 실패, 그리고
요청 로케일 본문이 DB에 없을 때 그것이 뜬다. 대가는 하나다 — **DB만 갱신되면 폴백이
구본으로 남는다.** 그래서 "DB만 고치면 끝"이 아니고, 본문을 갱신하면 이쪽에 알려줘야
완전히 반영된다(5절 4번).

폴백을 둔 이유는 개인정보처리방침이 **최초 실행 고지의 대상**이고 시작 화면 푸터가
재열람의 유일한 통로이기 때문이다. 매장 네트워크가 나빠 조회가 실패했다고 빈 창이 뜨면
고지 의무를 못 지킨 것이 된다.

### 3.4 전송량

이 3종은 합쳐 415행짜리 모듈이고, 로케일 사전에 넣지 않은 이유 자체가 첫 로드 전송량이었다
(첫 화면 전송량을 660KB 줄인 작업과 어긋나서). DB로 옮기면 **열 때만 받게 되어 오히려
유리하다** — 다만 조회를 시작 화면 마운트에 걸지, 창을 열 때 걸지는 이쪽에서 정한다.

## 5. 남은 일 (회신 부탁)

1. **본문이 아직 자리표시자다.** 2026-08-20 15:09 덤프 기준 세 문서 모두
   `{"ko": "…내용을 입력해주세요."}`이고 `en`은 아예 없다. 클라이언트는 **요청 로케일이
   DB에 있을 때만 DB를 쓰고**, 없으면 번들에 남겨 둔 기존 본문으로 떨어지게 해뒀다 —
   그래서 지금 화면에는 한국어만 자리표시자가 뜨고 영어는 기존 약관이 그대로 나온다.
   **확정 본문을 채워주면 그때부터 DB가 주 경로가 된다.**
   - 원문은 `docs/client/20260813_약관.zip`(기획자 확정본). 연락처·시행일까지 채운
     최종 전사본은 `gookbapgame/app/lib/legalDocs.ts`에 있으니 그대로 붙여넣으면 된다.
   - 붙여넣을 때 **3절의 평문 서식 규칙**(글머리 `· `, 빈 줄 문단, 곡선 따옴표)을
     그대로 지킬 것. HTML/마크다운은 그대로 글자로 보인다.
2. **`en`을 함께 채울 것.** 한쪽만 갱신되면 언어에 따라 다른 내용을 보게 된다.
   ja/zh는 3.2절 참고 — **본문을 채우는 것 자체는 정책 결정이 필요하다.**
3. **편집기의 안전장치**(2.3절): 빈 본문 저장 금지, 대괄호 자리표시자 저장 금지,
   부분 업데이트(Merge/Patch) 유지.
4. **본문을 갱신하면 알려줄 것.** 클라이언트에 폴백 본문이 남아 있어(3.3절) DB만
   고치면 폴백이 구본으로 남는다. 알려주면 이쪽이 함께 갱신한다.
5. **`updated_at`은 그대로 쓰고 있지 않다.** 클라이언트는 5분 TTL 메모리 캐시를 쓴다 —
   운영자가 고친 내용이 최대 5분 뒤에 반영된다. 즉시 반영이 필요하면 알려줄 것.
