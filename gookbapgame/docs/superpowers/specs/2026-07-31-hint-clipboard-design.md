# 힌트 클립보드 설계

작성일: 2026-07-31

## 1. 목적

게임 화면 하단의 힌트 버튼을 누르면 클립보드(집게 달린 나무 서류판) 이미지가 오버레이로 뜨고,
그 종이 영역에 이번 스테이지의 **차이 나는 슬롯들의 파츠 카테고리명**이 한 줄씩 표시된다.
감열지에 인쇄된 영수증/주문확인서 같은 인상을 목표로 한다.

현재 힌트 버튼은 `app/components/GameScreen.tsx:213-217`에 존재하지만 `onClick`이 없는 빈 버튼이다.

## 2. 표시할 내용

### 2.1 대상

**차이 나는 슬롯(`isDifference === true`)의 `part_categories.name`만** 표시한다.

`parts.name`(예: "마라국밥")이 아니라 카테고리명(예: "메인 국밥그릇")을 쓴다.
파츠명을 그대로 노출하면 정답을 알려주는 것과 다름없고, 카테고리명은 "어느 부위를 보라"는
수준의 힌트로 적절하다.

좌우 슬롯은 같은 `category_id`를 공유하므로 슬롯당 이름은 하나다.

### 2.2 줄 수

**차이 슬롯 1개당 1줄.** 이름이 중복되어도 합치지 않는다.

- 서로 다른 두 차이 슬롯이 같은 `category_id`를 가질 수 있다.
  `actions.ts`의 `dedupedSlots`는 `x,y,scale` 기준으로만 중복을 제거하므로 카테고리 중복을 막지 않는다.
- 이름을 dedupe 하면 차이 5개인 스테이지가 4줄로 보여 플레이어가 다 찾은 것으로 착각한다.
- 따라서 **줄 수 == `differenceSlots.length`** 를 항상 만족시킨다.

레벨과 무관하게 레벨당 최대 문제 수는 7개다(`STAGE_CONFIG` 기준 현재 최대 `diffCount: 7`).
다만 언어에 따라 긴 이름이 줄바꿈될 수 있으므로, **렌더링 기준 10줄이 종이 영역에 들어가도록**
공간과 폰트 크기를 잡는다. 긴 이름은 잘라내지 않고 줄바꿈한다.

### 2.3 로케일

`part_categories.name`은 jsonb이며 언어 코드(국가 코드 없음)를 키로 갖는다: `{"ko": "...", "en": "...", "ja": "..."}`.

해석 순서:

```
categoryName?.[locale] ?? categoryName?.ko ?? "—"
```

- 현재 로케일 키가 없으면 `ko`로 fallback.
- `ko`조차 없거나 카테고리 행 자체가 없으면 `"—"` 한 줄을 출력한다.
  **빈 문자열로 줄을 없애지 않는다** — 줄 수가 차이 개수와 어긋나면 안 되기 때문이다.

해석은 **클라이언트 컴포넌트에서** 수행한다. `app/actions.ts`는 서버 액션이고 `useLocale()`은
클라이언트 전용이므로, 서버에 로케일을 배선하지 않기 위해 jsonb 맵을 그대로 내려보낸다.

## 3. 데이터 배선

`part_categories` 테이블은 현재 어디서도 쿼리하지 않는다. 추가 작업:

1. `app/actions.ts`의 base_image 선택 루프가 끝나 `validSlots`가 확정된 뒤,
   `validSlots`의 `category_id` 집합으로 쿼리 1회 추가:

   ```ts
   const { data: categories } = await supabase
     .from("part_categories")
     .select("id,name")
     .in("id", categoryIds);
   ```

   실패하거나 비어 있어도 게임 진행은 막지 않는다(`categoryName: null`로 두고 `"—"` 표시).

2. `GameSlot` 타입에 필드 추가:

   ```ts
   categoryName: Record<string, string> | null;
   ```

   슬롯 조립 시(`slots: GameSlot[] = await Promise.all(...)`) 카테고리 맵에서 조회해 채운다.

`GameSession`의 다른 필드나 기존 흐름은 건드리지 않는다.

## 4. 오버레이 동작

토글이다. 힌트 버튼을 누르면 열리고, 다시 누르거나 배경을 클릭하면 닫힌다.
횟수 제한 없고 점수/시간 패널티도 없다.

### 4.1 오답 오탐 방지 (필수)

`GameScreen.tsx:183`과 `:201`의 양쪽 씬 컨테이너에 `onClick={handleBackgroundClick(side)}`가 걸려 있고,
이는 `registerWrongTouch()`로 이어져 **10점 감점 + 스테이지당 3회 제한 카운트 증가 + 3회 도달 시 강제 진행**을
일으킨다.

따라서 오버레이를 단순히 씬 위에 얹으면, 클립보드를 클릭하거나 닫으려고 바깥을 클릭하는 것만으로
오답 처리된다. "무료 힌트"가 실제로는 유료가 된다.

대응:

- `StageTransitionModal.tsx`와 같은 패턴의 전체 화면 백드롭(`fixed inset-0 z-50`)을 씬 위에 깐다.
- 백드롭 클릭 = 닫기.
- 클립보드 요소 자체는 `stopPropagation()`으로 클릭을 삼킨다.
- 힌트가 열려 있는 동안 씬 클릭은 백드롭에 가로막혀 애초에 도달하지 않는다.

### 4.2 상태

`GameScreen` 내부 `useState<boolean>` 하나면 충분하다. 스테이지가 바뀌어도 열린 채로 남지 않도록,
강제 진행/스테이지 클리어 시 닫는다.

## 5. 렌더링

### 5.1 애셋

`public/icons/hint-clipboard.webp` (1626×2624, alpha 포함).
원본: `.../gfx/assets/raw/Gemini_Generated_clipboard_alpha.webp`

### 5.2 배치

세로로 긴 비율(약 0.62)이므로 **높이 기준**으로 크기를 정한다. 폭 기준으로 잡으면 세로가 화면을 넘친다.

- 래퍼: `position: relative`, 높이를 뷰포트 기준으로 지정하고 폭은 종횡비에서 파생.
  좁은 화면에서도 넘치지 않도록 폭 상한을 함께 건다.
- 클립보드 `<img>`는 래퍼를 가득 채운다.
- 텍스트 블록은 래퍼 기준 `position: absolute`로 종이 영역에만 놓는다.
  초기 추정값(래퍼 크기 대비 백분율): `left 13% / right 18% / top 26% / bottom 14%`.
  상단 26%는 금속 집게가 종이를 덮는 구간을 피하기 위한 값이다.
  정확한 수치는 구현 중 눈으로 맞춘다.

### 5.3 타이포그래피

- `font-family: monospace` — CSS 범용 패밀리 키워드만 사용한다.
  구체적 폰트를 지정하거나 폰트 파일을 추가하지 않는다. 브라우저/OS가 고르게 둔다.
- 폰트 크기는 컨테이너 크기에 비례해야 한다. 고정 크기(`text-sm` 등)를 쓰면 좁은 화면이나
  10줄 상황에서 종이 밖으로 넘친다.
  뷰포트 단위 기반으로 `min(<vh>, <vw>)` 형태로 잡아 높이·폭 양쪽에서 안전하게 만든다.
  기준: **10줄 + 줄간격이 종이 영역 세로에 들어갈 것.**
- 좌측 정렬, 넉넉한 `line-height`, 잉크색은 완전한 검정보다 살짝 흐리게 하여 감열지 인쇄 느낌을 낸다.
  주의: 테마의 `--ink`는 어두운 배경용 밝은 색(`#F3E9DC`)이므로 `text-ink`를 쓰면 흰 종이에서 안 보인다.
  종이 위 글자는 별도의 어두운 색을 명시한다.

## 6. i18n

로케일 파일은 `app/lib/i18n/locales/` 아래 `ko.ts`, `en.ts`, `ja.ts` 세 개다.
단 `ja.ts`는 현재 의도적으로 비어 있고(`export const ja: Partial<Dictionary> = {}`),
`translate.ts`가 `ja → en → ko` 순으로 폴백한다. 이 관례를 따라 새 키는 **`ko.ts`와 `en.ts`에만** 추가한다.

필요한 키:

- 힌트 종이 상단 제목(영수증 헤더 역할) — 예: `game.hintTitle`
- 오버레이 닫기 aria-label — 예: `game.hintCloseAria`

기존 `game.hintButton`은 그대로 쓴다.

## 7. 테스트

- `part_categories.name` 로케일 해석: 현재 로케일 키 존재 / `ko` fallback / 둘 다 없음(`"—"`) 세 경우.
- 차이 슬롯 2개가 같은 카테고리일 때 줄이 2줄로 유지되는지.
- 줄 수가 `differenceSlots.length`와 일치하는지.
- 카테고리 쿼리가 실패해도 게임 세션이 정상 생성되는지.

오버레이 클릭이 오답으로 집계되지 않는지는 수동 확인한다(백드롭이 씬 클릭을 가로막는 구조 자체가 보장).

## 8. 범위 밖

- 힌트 사용에 대한 점수/시간 패널티
- 이미 찾은 항목의 취소선 처리
- 카테고리명 외의 추가 힌트 정보(위치, 축소 이미지 등)
- `parts.name`을 쓰는 상위 난이도 힌트
